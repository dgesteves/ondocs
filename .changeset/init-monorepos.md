`ondocs init` works in monorepos. At a workspace's root with no site config of its own, it lists the packages that have one and says which folder to run it in, instead of taking a dependency of the root's for an Astro site. In the site's package, it finds a `netlify.toml`, `vercel.json` or wrangler config in a folder above, up to the workspace's or the repository's root, asks whether it serves the site (or takes `--yes` or `--host`), and writes the functions where that host builds from (Netlify's `base`), with the index's path from there, such as `website/build/ask-index.json`. Before, it found no host there, and with `--host netlify` it wrote a second `netlify.toml` and the functions in the site's folder, which Netlify ignores. The install steps use the workspace's package manager: `pnpm --filter <package> add` or `yarn workspace <package> add` for the site, and `pnpm add -w` or `yarn add` at the root for functions there, where init said `npm i` because the lockfile was not in the site's folder.

The Netlify Functions init writes read the index by its path from their own file, not from the working directory. Netlify runs a function from the root of its bundle, which in a workspace that installs its dependencies at its root is the workspace's root, so for a site in one of its packages the functions looked for the index where it was not, and `/api/mcp` answered with a 500.

init finds more of a site's locales, so their pages are not answered from the default locale's index: Starlight's `locales,` from a const in the same file, as Starlight's own docs have it, Docusaurus's `i18n` imported from another file, as Jest's site has it, and the locales the last build wrote an index for, with a warning where those and the config disagree, or when the config makes its locales in code init does not read. A VitePress locale that only links to another site gets no index, and Astro's `{ path, codes }` locales are read by their path, once each, where init wrote a duplicate key and a `pt-BR` index that never exists. A commented-out `defaultLocale` is no longer taken for the site's, and Starlight's shorthand `site,` counts as a site URL, where init said to set one first.

On a Cloudflare Worker's `wrangler.json`, an empty `"assets": {}` gets the binding without a trailing comma, which made the file invalid JSON, and only a top-level `"main"` counts as the Worker's own entry point, so an `env.staging.main` no longer stops init.
